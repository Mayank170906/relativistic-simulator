relativistic-simulator

A research-grade, lightweight Python simulator for 1D special-relativistic massive-particle dynamics under a constant external force. It is a ground-truth physics engine for machine-learning research: it generates exact synthetic data from known equations of motion — it does not discover physics, and it contains no ML model itself.

01 Reading NumPy's numbers (read this first!)

This library runs on NumPy and does relativistic physics, so it deals in both extremely small and extremely large numbers — speeds close to the speed of light, forces in the millions of newtons, gamma factors that blow up toward infinity. If you have not used NumPy / scientific Python before, the printed numbers can look alarming at first. They are not bugs.

⚠️
You may see numbers like 1e6, 2.998e8, or even something like 1e223. This is scientific notation, not an error, not "infinity", and not a sign that the simulation blew up (unless you specifically hit an overflow — see below).

The letter e here always means "times ten to the power of", exactly like the E button on a scientific calculator — it has nothing to do with Euler's number or the base of natural logarithms. The exponent-first magnitude (positive exponent) makes the number huge; a negative exponent makes it tiny. Every result in this package is a standard IEEE-754 double-precision float (float64), the same numeric type used throughout NumPy, so its printed form always follows this convention.

Why relativity produces such extreme numbers

As a particle's speed v approaches the speed of light c, the Lorentz factor gamma = 1/sqrt(1 - (v/c)²) grows without bound. At beta = v/c = 0.99999, gamma is already about 223.6; push beta close enough to 1 and gamma (and therefore momentum and energy) can legitimately reach values like 1e10, 1e50, or beyond, purely because that is what the physics says happens near the speed of light. This package deliberately does not clip or silently round these values — if a computation is mathematically valid but numerically extreme, you will see it in scientific notation instead of it being hidden from you.

💡
Formatting tip If you want fixed-point output for a report or a plot, format explicitly instead of relying on the default repr: f"{value:.6f}" or numpy.set_printoptions(suppress=True) for arrays. This package never changes NumPy's global print options for you, since that would silently affect the rest of your program.

02 The physics, briefly

You do not need a relativity textbook to use this package, but a few terms recur throughout the API. Here is the whole model in plain language, then the equations it solves exactly.

🧲 The setup

A single massive particle of constant rest mass m moves along one spatial axis and is pushed by one constant force F, in flat (Minkowski) spacetime — no gravity, no curved spacetime, no fields.

β (beta)

Velocity as a fraction of light speed: beta = v / c. Always strictly between -1 and 1 for a massive particle.

γ (gamma)

The Lorentz factor gamma = 1/sqrt(1-beta²). Equals 1 at rest and grows toward infinity as beta approaches 1.

Momentum

Relativistic momentum is p = gamma*m*v, not the classical m*v. This is the quantity the constant force actually acts on.

Proper time τ

Time as experienced by the moving particle itself, always ≤ the "lab frame" time t, via dτ = dt / gamma.

Why not F = m·a?

Newton's second law in its momentum form, dp/dt = F, is what's actually true in relativity. Because p depends nonlinearly on v through gamma, this is not the same as classical F = m*a once beta becomes significant.

The governing equation

The whole simulator is one equation of motion, dp/dt = F, with p = gamma*m*v, solved exactly in closed form (an analytic solution, not a numerical approximation) for a constant force:

p(t) = p0 + F·t
q(t) = p(t) / (m·c)
gamma(t) = hypot(1, q(t))
v(t) = c·q(t) / gamma(t)
E(t) = c·hypot(m·c, p(t)) # total energy
K(t) = p(t)²·c² / (E(t) + m·c²) # kinetic energy
x(t) = x0 + c·t·(q(t) + q0) / (gamma(t) + gamma0) # F ≠ 0

This position formula is algebraically equivalent to the more obvious (K - K0) / F, but it avoids catastrophic floating-point cancellation at very high beta and very small impulses. Proper time is computed with a numerically stable log1p-based rapidity form rather than a naive integral. See docs/physics.md in the repository for full derivations. simulate(method="numerical") additionally offers an independent RK4 integrator as a cross-check against the closed-form solution.

How the modules depend on each other

constants.py and exceptions.py sit at the bottom with no internal dependencies. relativity.py builds on them to provide pure conversion functions (velocity ↔ beta ↔ gamma ↔ momentum ↔ energy). dynamics.py and simulator.py use relativity.py to produce a full time series, wrapped as a Trajectory. dataset.py vectorizes simulator.py across many random parameter sets. validation.py independently re-derives the same physical relationships to sanity-check both trajectories and datasets. classical.py and plotting.py are optional, self-contained utilities that nothing else in the physics core depends on.

05 Quick start

The smallest useful example: simulate a particle and inspect the result.

from relativistic_simulator import C, simulate

result = simulate(
    mass=1000.0,             # kg
    force=1e6,                # newtons — see the "Reading NumPy's numbers" section above
    initial_velocity=0.9 * C,  # 90% of the speed of light
    duration=100.0,            # seconds of simulated time
    dt=0.01,                   # time-step size, seconds
)

print(result.beta)             # v/c at every time step, as a NumPy array
print(result.gamma)            # Lorentz factor at every time step
print(result.momentum)         # relativistic momentum, kg*m/s
print(result.kinetic_energy)   # joules
print(result.total_energy)     # joules (rest + kinetic)
print(result.proper_time)      # seconds, as experienced by the particle
print(result.validate().summary())

simulate() returns a Trajectory object exposing arrays for time, position, velocity, beta, gamma, momentum, kinetic_energy, total_energy, and proper_time, plus convenience methods to_numpy(), to_dict(), to_dataframe() (requires the pandas extra), and final_state().

06 Step-by-step tutorial

A guided walkthrough for someone using this package for the first time.

  1. Install the package

    Run pip install "relativistic-simulator[all]" in a virtual environment so you also get plotting and dataframe support.

  2. Pick physical inputs

    Decide on a mass (kg), a constant force (newtons), an initial_velocity (m/s — often expressed as a fraction of C, e.g. 0.5 * C), a duration (seconds), and a time step dt (seconds). Smaller dt gives a finer-grained trajectory but does not change the exact analytic result at the endpoints.

  3. Call simulate()

    This returns a Trajectory. Nothing is plotted or saved automatically — you decide what to do with the arrays next.

  4. Inspect results, expect scientific notation

    Printing result.gamma near high beta will show values like 7.089e+00 — revisit the notation section above if this looks unfamiliar. Use result.final_state() for a plain dictionary of the last time step's values.

  5. Validate the physics

    Call result.validate() to get a TrajectoryValidation report that independently re-checks momentum, energy, the energy–momentum invariant, and more. Call .summary() for a human-readable printout, or .passed for a boolean.

  6. (Optional) plot it

    With the [plot] extra installed: from relativistic_simulator.plotting import plot_trajectory; plot_trajectory(result, path="trajectory.png").

  7. (Optional) generate a full dataset

    For ML experiments, use generate_dataset(...) instead of calling simulate() in a loop — it is vectorized and much faster. See Dataset generation below.

08 Dataset generation

For ML research you typically want many trajectories at once, not one at a time. generate_dataset() is fully vectorized with NumPy — it does not loop over simulate() in Python. 

from relativistic_simulator import generate_dataset

dataset = generate_dataset(
    n_samples=100_000,
    mass_range=(100.0, 10_000.0),
    force_range=(1e4, 1e7),
    beta_range=(0.0, 0.8),
    time_range=(0.0, 100.0),
    random_seed=42,
)

dataset.to_csv("train.csv")
print(dataset.input_columns)
print(dataset.output_columns)
print(dataset.validate().summary())

It uses numpy.random.default_rng internally (never NumPy's legacy global random state), so the same random_seed always reproduces the same dataset regardless of what else your program has done with randomness. Inputs are mass, force, initial_velocity, initial_beta, and time; targets are the exact position, velocity, beta, gamma, momentum, kinetic_energy, total_energy, and proper_time.

Defining your own regimes

Beta ranges are configurable, not hard-coded — useful for train/extrapolation splits in an ML experiment:

low           = generate_dataset(beta_range=(0.0, 0.5),    random_seed=1)
relativistic  = generate_dataset(beta_range=(0.5, 0.9),    random_seed=2)
ultra         = generate_dataset(beta_range=(0.9, 0.9999), random_seed=3)
training      = generate_dataset(beta_range=(0.0, 0.8),    random_seed=42)
extrapolation = generate_dataset(beta_range=(0.8, 0.9999), random_seed=43)

These match the pre-generated CSVs shipped under examples/output/ — see Worked examples.

09 Validation

Every result can be independently checked, rather than trusted blindly. This matters especially for ML pipelines, where a silent physics bug would poison an entire training set. 

report = result.validate()
print(report.max_energy_momentum_error)
print(report.max_force_error)
print(report.max_velocity_difference_error)
print(report.passed)

validate_trajectory and validate_dataset check p = gamma·m·v, E = gamma·m·c², the energy–momentum invariant, central finite differences for dp/dt and dx/dt, proper time, initial conditions, the velocity bound (|v| < c), and τ ≤ t. Crucially, these checks use routes that are independent of the generating formulas — e.g. checking momentum via a finite-difference derivative of position, not by re-running the same closed-form expression — so a validation pass is real evidence, not a tautology. Full details are in docs/validation.md.

10 Worked examples

Four runnable scripts live in examples/. Run any of them with uv run python examples/<name>.py, or plain python examples/<name>.py in an environment where the package is installed.

1. basic_simulation.py — low-speed sanity check

A 1000 kg object at rest, pushed by 106 N for 100 s. At this low speed the relativistic and classical predictions should nearly agree — this example prints both side by side as a sanity check that the exact and Newtonian pictures converge at low beta: 

from relativistic_simulator import C, simulate

result = simulate(mass=1000.0, force=1e6, initial_velocity=0.0,
                  duration=100.0, dt=0.01)
final = result.final_state()

classical_v = (1e6 / 1000.0) * 100.0              # v = (F/m)*t, Newtonian
classical_K = 0.5 * 1000.0 * classical_v**2

print(final['beta'], final['gamma'], final['kinetic_energy'], classical_K)

2. high_beta.py — velocity saturation near c

Sweeps the initial beta through 0.5, 0.7, 0.8, 0.9, 0.95, 0.99, 0.999, 0.9999, 0.99999 and shows the key relativistic effect: the same constant force and duration move a slow particle a lot, but barely nudge an already-fast particle's speed — even though its momentum and kinetic energy keep growing without bound. This is exactly the regime where you'll see the scientific-notation values discussed earlier (e.g. gamma_f in the hundreds and kinetic_energy in the 1e19+ range). 

BETAS = (0.5, 0.7, 0.8, 0.9, 0.95, 0.99, 0.999, 0.9999, 0.99999)

for b0 in BETAS:
    result = simulate(mass=1000.0, force=1e6, initial_velocity=b0 * C,
                      duration=100.0, dt=0.05)
    report = result.validate()
    assert report.passed
    print(b0, result.beta[-1], result.gamma[-1], result.kinetic_energy[-1])

# Observe: the impulse F*t barely changes beta near c, while gamma and
# momentum keep increasing. Velocity saturates below c but never reaches it.

3. generate_dataset.py — building train/extrapolation CSVs

Produces the CSVs shipped under examples/output/: train_beta_0_0.8.csv (a training regime up to beta 0.8) and extrap_beta_0.8_0.9999.csv (an extrapolation regime from 0.8 up to 0.9999) — a ready-made train/test split by relativistic regime for an ML experiment studying whether a model can generalize into the ultra-relativistic range it was never trained on.

4. benchmark.py — performance

Times vectorized dataset generation at various sizes so you know what throughput to expect before generating a very large dataset. See docs/benchmarks.md for reference numbers.

11 Precision and limitations

Know what this package is and is not before relying on it.

✅ What it models

1D special-relativistic dynamics of one massive particle under one constant external force, in flat spacetime, using IEEE-754 float64 throughout.

🚫 What it does not model

Gravity, curved spacetime, electromagnetic fields, variable mass, radiation reaction, quantum effects, or faster-than-light / spacelike trajectories.

Strict subluminal check

The package rejects |v| >= c outright — it never clips velocities down to just under c to "make it work". It also rejects states so extreme that float64 cannot represent a strictly subluminal velocity.

No ML inside

This is the "teacher" generating exact ground truth, not a "student" model. Any ML that learns from this data lives in a separate project.
